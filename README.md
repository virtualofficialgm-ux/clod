# Parri Pay

Parri Pay — продукт для оплаты услуг, выплат исполнителям и подключения финансовых возможностей к сервисам бренда (Tasks, Fit, Food и другим). На первом этапе он работает поверх инфраструктуры банков и платёжных провайдеров. Собственная платёжная система — отдельная долгосрочная программа, в этом коде она не включается.

Это рабочий прототип уровня **Pay Connect** с включаемыми возможностями **Pay Platform**. Он состоит из сервера на Node.js и веб-интерфейса. Внешних зависимостей нет, данные хранятся в памяти. Банки-партнёры заменены песочницами, которые ведут себя как настоящие провайдеры: у них своё состояние, идемпотентность, страница оплаты и подписанные вебхуки.

## Запуск

```bash
npm start                 # Pay Connect, http://localhost:3000
npm run start:platform    # + API для бизнеса, сверка, антифрод, кабинет бизнеса
npm test                  # тесты (node:test)
```

Демо без сервера: `npm run build:standalone` собирает `dist/parri-pay.html`. Этот файл открывается в браузере напрямую, сервис и тестовые банки работают внутри страницы.

Нужен Node.js 20 или новее. Порт задаётся переменной `PORT`, уровень — `PARRI_PAY_LEVEL` (`connect` | `platform`).

В интерфейсе вверху выбирается пользователь песочницы. Анна платит, Борис — исполнитель, Parri Fit и Parri Food — бизнес-счета. На вкладке «Рынки и уровни» есть кнопки песочницы: обработать операции партнёров, провести расчёт и сдвинуть часы, чтобы продлились подписки.

## Что умеет

| Возможность | Где |
|---|---|
| Единая платёжная форма с раскрытием комиссий | «Оплатить», `POST /api/quote`, `POST /api/orders/:id/payments` |
| История операций со статусами и резервированием | «История», `GET /api/me/operations` |
| Подписки с автопродлением | «Подписки», `POST /api/subscriptions` |
| Выплаты с учётом лимитов идентификации | «Выплаты», `POST /api/payouts` |
| Возвраты, полные и частичные | `POST /api/orders/:id/refunds` |
| Документы: чек, акт, отчёт о поступлении, чек возврата, подтверждение выплаты | «Документы» |
| Уведомления участникам | «Кошелёк» |
| Кабинет бизнеса и сверка с партнёрами (Platform) | «Бизнес», `/api/business/*` |

### Баланс не смешивает разные деньги

Кошелёк показывает отдельно:

- **Доступно** — реальные деньги после расчёта партнёра. Только их можно вывести.
- **Ожидаемые поступления** — то, что ждёт расчёта партнёра, и резерв по заказам, где пользователь исполнитель.
- **Временно недоступно** — резерв по собственным покупкам и выплаты в обработке.
- **Бонусы** — отдельная единица `BONUS` в учёте. Это не деньги, они не выводятся и не складываются с балансом.
- **Ограничения** — уровень идентификации, лимит платежа, месячный лимит выплат и остаток.

### Комиссии раскрываются раздельно

Комиссия эквайринга (партнёра), комиссия Parri и стоимость конвертации — это три отдельные строки в форме оплаты, в чеке, в акте и в кабинете бизнеса.

## Как проходит операция

```
Продукт (Tasks/Fit/Food)  ──создаёт заказ──▶  Parri Pay  ──платёжное поручение──▶  Партнёр
                                                 ▲                                    │
                                                 └──── подписанное уведомление ◀──────┘
Parri: проверка подписи → дедупликация события → проводка в учёте → уведомления
       → следующий разрешённый шаг (резерв / зачисление / продление подписки)
```

1. Сервис бренда создаёт заказ: `POST /api/service/orders` с ключом сервиса. Заказ уникален по паре `product + externalRef`, поэтому повторный запрос вернёт тот же заказ.
2. Плательщик запускает оплату. Parri создаёт платёжное поручение и передаёт партнёру его `id` как ключ идемпотентности. Плательщик вводит карту на странице партнёра, и данные карты к Parri не попадают.
3. Партнёр присылает уведомление `payment.succeeded`. Parri проверяет HMAC-подпись и сумму, затем отражает оплату в учёте.
4. Дальше зависит от продукта:
   - **Tasks**: деньги остаются в резерве (`escrow:<order>`), пока плательщик или сервис не подтвердит выполнение. После подтверждения исполнителю начисляется ожидаемая выплата за вычетом комиссий.
   - **Fit / Food**: сумма сразу зачисляется бизнесу как ожидаемая.
5. Расчёт партнёра (T+N дней, своё значение для каждого рынка) переводит ожидаемые средства в доступные.

### Защита от двойного списания

| Уровень | Механизм |
|---|---|
| HTTP | Заголовок `Idempotency-Key`. Повтор с тем же ключом возвращает сохранённый результат, тот же ключ с другими параметрами даёт `409`. |
| Заказ | Уникальность `product + externalRef`. У заказа только один активный платёж, поэтому двойной клик вернёт тот же платёж. |
| Партнёр | `id` платёжного поручения, возврата или выплаты передаётся партнёру как ключ идемпотентности. |
| Уведомления | Каждое событие обрабатывается один раз (`partner:eventId`). Песочница специально доставляет каждое событие дважды. |
| Учёт | У каждой проводки уникальный `operationId` (`capture:<payment>`, `release:<order>`…). Повторная проводка не двигает деньги. |
| Статусы | Машина состояний платежа запрещает откаты: если после успеха придёт уведомление `failed`, оно будет проигнорировано. |
| Подписки | Отдельный заказ на каждый период (`sub:<id>:<period>`). Повторный запуск биллинга не спишет период дважды. |

Если партнёр подтвердил платёж, который Parri уже считала отменённым, деньги отражаются в учёте и возвращаются автоматически.

## Учёт

Учёт двойной записи (`src/ledger.js`). Каждая проводка состоит из переводов между счетами, и сумма всех остатков в каждой валюте всегда равна нулю. Это проверяется в тестах. Остатки на счетах пользователей, резервов, выплат и бонусов не могут уйти в минус.

| Счёт | Смысл |
|---|---|
| `external:<partner>` | зеркало денег у партнёра |
| `escrow:<order>` | резерв по заказу |
| `user:<id>:pending` / `merchant:<id>:pending` | ожидает расчёта партнёра |
| `user:<id>:available` | доступно к выплате |
| `payout:<id>`, `refund:<id>` | средства, заблокированные на время обработки партнёром |
| `revenue:parri_fee`, `revenue:fx`, `expense:acquiring` | доходы и расходы Parri |
| `bonus:<id>` (валюта `BONUS`) | бонусы — не деньги |

Правила возврата:

- **До завершения заказа** деньги возвращаются из резерва. Комиссия эквайринга остаётся расходом Parri.
- **После завершения** сумма списывается у получателя, а Parri возвращает получателю свою комиссию пропорционально сумме возврата. Если у получателя не хватает средств, нужна ручная обработка.
- **Стоимость конвертации** не возвращается, это указано в чеке возврата.

## Три уровня развития

| Уровень | Содержание | Условие перехода | В коде |
|---|---|---|---|
| Pay Connect | Интеграция приёма платежей и выплат | Работающий основной продукт и договоры с партнёрами | включён по умолчанию |
| Pay Platform | API, сверка, антифрод и кабинет бизнеса | Подтверждённый объём операций и надёжный учёт | `PARRI_PAY_LEVEL=platform` |
| Pay Network | Собственные правила участия и расчётная модель | Отдельная оценка регулирования, капитала и сети участников | не включается: запуск с `network` завершится ошибкой |

Какой возможности нужен какой уровень, задано в `CAPABILITIES` в `src/config.js`. Если возможность недоступна на текущем уровне, API отвечает `403` и называет условие перехода.

## Рынки

Единый интерфейс не означает единого банка. Для каждого рынка в `MARKETS` (`src/config.js`) задаются свой партнёр, валюта расчётов, валюты оплаты, срок расчёта, процедуры идентификации и лимиты. Расчёты между рынками на уровне Connect не поддерживаются.

Кредитование, приём вкладов и выпуск карт помечены как `regulated` и выключены на всех рынках. Их можно добавить только через соответствующую разрешённую модель.

## Монетизация

Доход Parri в учёте: сервисная комиссия (`revenue:parri_fee`, ставка задаётся в продукте) и маржа на конвертации (`revenue:fx`). Подписки для бизнеса и вознаграждение от партнёров — договорные потоки, в прототипе они не моделируются.

## Структура

```
src/config.js               уровни, рынки, продукты, партнёры, ключи песочницы
src/money.js                деньги в минимальных единицах, конвертация, ошибки
src/fees.js                 раскладка комиссий
src/ledger.js               учёт двойной записи
src/idempotency.js          идемпотентность запросов

src/services/reconciliation.js  сверка с отчётом партнёра (Platform)
src/partners/sandbox.js     песочница банка-партнёра и подпись вебхуков
src/http/                   HTTP API, страница оплаты партнёра, документы
public/                     веб-интерфейс
test/                       тесты
```

## Ограничения прототипа

- В песочнице пользователь определяется заголовком `X-User-Id`. В продукте здесь будет сессия или OAuth бренда.
- Данные хранятся в памяти. Хранилище (`src/store.js`) спроектировано так, чтобы его можно было заменить транзакционной БД. Вызов партнёра и проводки при этом нужно разделить через outbox.
- Партнёры — песочницы. Чтобы подключить реальный банк, нужно реализовать адаптер с тем же интерфейсом (`createPayment`, `createRefund`, `createPayout`, подписанные уведомления, отчёт для сверки).
- Курсы валют и тарифы — тестовые.
